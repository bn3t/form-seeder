Form Seeder

Named test-data profiles mapped to forms via CSS selectors and URL glob patterns.

URL pattern help

  • Patterns are globs: * matches any text including /. https://myapp.be/users/* also matches /users/new/confirm.
  • Patterns must match the whole URL (they are anchored), e.g. https://*.myapp.be/billing/*.
  • The #fragment is ignored. If a pattern has no ?, any query string is accepted (.../users/new matches .../users/new?ref=admin). A pattern containing ? is matched literally against the full URL.
  • Trailing slashes are ignored: /users/new ≡ /users/new/.
  • Page selector (optional): when the URL alone doesn't identify the page, add a CSS selector (e.g. form#user-create). The matcher is then only active when the URL matches and that selector exists in the page's DOM, checked when the popup opens. Use a broad URL pattern like https://local.myapp.dev/* and let the page selector do the discrimination.

Field values

  • Checkbox/radio: value "true" or "1" checks, anything else unchecks. Target a specific radio with e.g. input[name=gender][value=f] and value "true".
  • <select>: the value must equal an option's value attribute, not its visible text.
  • Date/time inputs need exact formats: date yyyy-mm-dd, time HH:MM, datetime-local yyyy-mm-ddTHH:MM. Wrong format leaves the field empty (browser behavior).
  • Only the first element matching a selector is filled. Selectors that match nothing are skipped and reported after filling.
